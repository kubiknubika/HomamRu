# Игровое состояние и команды

Статус: принято владельцем 2026-11-11. Этап 1.

Это основа ядра. На ней держатся сохранения, дамп ошибки, сценарии, компьютерный противник и будущая сетевая игра (догмы 6 и 7).

## Состояние

Игровое состояние — всё, что нужно, чтобы продолжить партию с этого места.

Правила для состояния:

- Это обычные данные: объекты, списки, строки, целые числа, логические значения и пустое значение `null` («нет»: шахта ничья, боя нет). Его можно превратить в JSON и обратно без потерь.
- Дробных чисел в состоянии нет. Все игровые величины целые.
- Идентификаторы — строки.
- Состояние никогда не меняется на месте. Команда возвращает новое состояние.
- В состоянии есть номер версии формата (`version`). Он увеличивается при любом изменении формата.

Состав состояния на этапе 1:

| Поле | Что это |
|---|---|
| `version` | номер версии формата состояния |
| `rng` | состояние генератора случайных чисел |
| `map` | карта: размеры и местность (см. `01-adventure-map.md`) |
| `players` | список игроков по порядку хода |
| `heroes` | список героев: идентификатор, владелец, клетка, остаток запаса хода |
| `day` | номер дня партии, начиная с 1 |
| `currentPlayer` | номер игрока, чей сейчас ход |

Карта хранится внутри состояния целиком, чтобы сохранение не зависело от файлов карт. Вместе с местностью хранятся стартовые клетки игроков (`map.starts`, из файла карты; в игре не меняются): на них ставится герой, у которого в сохранении нет клетки (`04-save.md`).

Номер игрока в состоянии считается с нуля: первый игрок — 0, второй — 1. Игрок на экране и в текстовом выводе видит номера с единицы.

Идентификатор героя на этапе 1 — буква игрока: `A` у первого, `B` у второго.

## Создание партии

Партия создаётся функцией «создать игру» из описания карты и сида. Это не команда: до неё состояния ещё нет.

Создание проверяет карту по смыслу (см. `01-adventure-map.md`). Если карта неверна, партия не создаётся, а ошибка называет причину.

## Команды

Команда — единственный способ изменить состояние. Команду отправляет игрок через интерфейс, компьютерный противник или сценарий.

У каждой команды есть тип и номер игрока, который её отдал.

Применение команды — функция: состояние и команда на входе, результат на выходе. Результат бывает двух видов:

- **Принята:** новое состояние и список событий.
- **Отклонена:** код ошибки и сообщение. Состояние не меняется вообще.

Команда применяется целиком или не применяется совсем. Частичного применения нет.

Команды этапа 1:

| Команда | Что делает | Документ |
|---|---|---|
| Переместить героя | ведёт героя по заданному пути | `02-hero-movement.md` |
| Закончить ход | передаёт ход следующему игроку | `03-time.md` |

## Общие причины отказа

| Код | Когда |
|---|---|
| `NOT_YOUR_TURN` | команду отдал не тот игрок, чей сейчас ход |
| `UNKNOWN_PLAYER` | игрока с таким номером нет |
| `UNKNOWN_COMMAND` | неизвестный тип команды |

Остальные причины отказа описаны в документах команд.

Если причин несколько, называется первая по порядку: сначала общие в порядке этой таблицы снизу вверх (неизвестная команда, неизвестный игрок, не тот ход), затем причины самой команды в порядке её таблицы.

## События

Событие — запись о том, что произошло. Список событий, который возвращает принятая команда, и есть журнал.

- События идут в том порядке, в котором всё происходило.
- По событиям интерфейс показывает анимацию, а текстовый вывод печатает ход игры.
- События — тоже обычные данные.

## Запросы

Запрос ничего не меняет, а только отвечает на вопрос: «какой путь до этой клетки», «куда герой дойдёт сегодня». Запросами пользуются интерфейс и компьютерный противник.

На этапе 1 есть запрос пути. Запрос «куда герой дойдёт сегодня» появится на этапе 5, вместе с компьютерным противником.

## Детерминизм

- Одинаковое начальное состояние и одинаковый список команд дают одинаковое конечное состояние и одинаковый журнал. Всегда и на любом устройстве.
- Случайность берётся только из генератора в состоянии.
- Порядок обхода списков всегда определён: по порядку в списке, а не «как получится».

## Повтор партии

Партия — это начальное состояние и список принятых команд. Функция «повторить» применяет команды по очереди и возвращает конечное состояние и полный журнал.

Обязательный тест: повтор одной и той же партии дважды даёт одинаковый результат; состояние после превращения в JSON и обратно даёт тот же результат, что и без превращения.

## Версии

Формат состояния можно дополнять: сохранение другой версии читается, недостающее берётся из таблицы начальных значений, незнакомое убирается (см. `04-save.md`, «Сохранения других версий»). Каждый новый параметр обязан получить начальное значение в этой таблице. Изменение смысла уже существующего параметра требует отдельного переноса (догма 10).

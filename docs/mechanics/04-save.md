# Автосохранение

Статус: принято владельцем 2026-11-11. Этап 1. Раздел «Сохранения других версий» переписан по слову владельца 2026-11-12: раньше сохранение другой версии отбрасывалось.

## Что видит игрок

- Сохранение одно. Игра ведёт его сама, кнопки «сохранить» нет.
- При запуске, если есть сохранённая партия, игра предлагает «Продолжить» и «Новая игра».
- «Новая игра» при существующем сохранении спрашивает подтверждение: старая партия будет потеряна.

## Когда игра сохраняется

После каждой принятой команды.

Владелец решил сохранять «в конце каждого дня и при сворачивании приложения» (решение 0003). Сохранение после каждой команды включает оба случая и защищает ещё от одного: приложение закрыли или оно упало посреди дня. Сохранение маленькое, поэтому на скорости это не сказывается. Владелец согласился 2026-11-11.

Если команды идут быстрее, чем пишется файл, на диск попадает только самая свежая запись из очереди.

## Что лежит в сохранении

| Часть | Зачем |
|---|---|
| версия формата сохранения и версия формата состояния | для дампа ошибки; на загрузку не влияют |
| версия игры | для дампа ошибки |
| текущее состояние | из него партия продолжается |
| начальное состояние и список принятых команд | для дампа ошибки и проверки повтором |
| порядковый номер записи | чтобы выбрать более свежую из двух копий |
| контрольная сумма | чтобы распознать испорченную запись |

Партия продолжается из текущего состояния, а не повтором команд с начала.

## Надёжность записи

Приложение могут закрыть прямо во время записи. Поэтому:

- Хранятся две копии сохранения. Новая запись идёт поверх более старой копии.
- При загрузке берётся копия с верной контрольной суммой и большим порядковым номером.
- Если последняя запись оборвалась, игра продолжается с предыдущей: теряется не больше одной команды.

## Где хранится

Ядро ничего не знает о хранилище. Клиент пишет сохранение через общий интерфейс «хранилище сохранений» с двумя реализациями:

- **Android:** файлы `save-0.txt` и `save-1.txt` в личной папке приложения, через дополнение Capacitor «Файлы» (`@capacitor/filesystem`, согласовано владельцем 2026-11-11).
- **Браузер (превью):** хранилище браузера.

В документации Capacitor сказано, что хранилище браузера внутри приложения система может очистить при нехватке места, поэтому на Android оно не используется: `docs/vendor/capacitor/guides/storage.md`.

## Вид записи

Запись — текст из двух строк: контрольная сумма (FNV-1a, 32 бита, восемь шестнадцатеричных цифр) и JSON с остальными частями. Версий в записи две: формата сохранения и формата состояния. Загрузке они не мешают: см. «Сохранения других версий».

## Новая игра

- Если сохранения нет, игра сразу начинает новую партию, без экрана выбора.
- Новая партия сразу записывается поверх прежней.
- «Новая игра» есть и в меню; она тоже спрашивает подтверждение. Отладочная кнопка выбора карты начинает новую партию и поэтому спрашивает так же.

## Сохранения других версий

Игра загружает сохранение любой версии — и более старой, и более новой. Номера версий при загрузке не сравниваются. Запись читается по трём правилам:

1. **Чего в записи нет — берётся начальное значение** из таблицы ниже. Так читается сохранение старой версии: в нём ещё не было новых параметров. То же происходит, если значение есть, но не читается (например, текст на месте числа или отрицательный запас).
2. **Чего игра не знает — убирается.** Так читается сохранение более новой версии: незнакомые поля, незнакомые объекты карты и незнакомые символы местности стираются без ошибки. Продолжив такую партию, игрок теряет стёртое навсегда: следующая запись делается уже в формате этой версии.
3. **Без чего партию не продолжить — сохранение считается повреждённым.** Такое значение одно: местность карты. Придумать её нельзя.

Если при чтении что-то было дописано или убрано, игра говорит об этом на экране «Продолжить / Новая игра»: «Сохранение сделано другой версией игры. Чего в нём не хватало — взято начальное, незнакомое убрано».

### Начальные значения

| Параметр | Начальное значение |
|---|---|
| номер версии состояния | всегда ставится текущий |
| состояние генератора случайных чисел | 0 |
| идентификатор карты | `unknown` |
| название карты | «Без названия» |
| ширина и высота карты | всегда считаются по местности |
| местность | **нет**: сохранение повреждено. Строки разной длины или карта без единой клетки земли — тоже. Незнакомый символ заменяется обычной землёй `.` |
| стартовые клетки игроков | пустой список. Клетка вне карты или не на земле заменяется первой клеткой земли (если читать карту по строкам) |
| список игроков | столько игроков, сколько нужно героям и шахтам, но не меньше одного |
| номер игрока | всегда равен месту в списке |
| запас каждого ресурса | 0 |
| список героев | по одному герою каждому игроку. Запись героя, которая вовсе не читается, убирается |
| клетка героя | стартовая клетка его игрока; если её в записи нет — первая клетка земли. Так же, если клетка вне карты |
| владелец героя | место героя в списке (но не дальше последнего возможного игрока) |
| идентификатор героя | по владельцу: `A`, `B` |
| кто герой (идентификатор из файла героев) и его имя | первый герой списка героев партии и его имя (в записях до шага 4.2 имён нет). Так же, если записан герой, которого в списке нет. Атака и защита при этом остаются как записаны |
| список героев партии | герои из файла `data/heroes.yaml`. Записанные остаются как записаны; героев игры, которых в записи нет, дописывают в конец |
| правила таверны (цена героя, его случайная армия) | из файла `data/defaults.yaml`. Так же, если записанные правила не читаются целиком или называют незнакомое существо |
| настройки компьютерного игрока (перевес для нападения, список стройки) | из файла `data/defaults.yaml`. Так же, если записанные настройки не читаются целиком или называют незнакомое здание |
| таверна игрока | у игрока без города — пусто, что бы ни было записано. У игрока с городом — два героя: читаемые записи остаются (кроме героя игрока, повторов, незнакомых героев и героев без армии; незнакомые существа из армии убираются), а недостающие места занимают первые свободные герои списка с наименьшей армией из отрядов, которые есть всегда (сейчас 10 ополченцев). Случайные числа при чтении не тратятся |
| остаток хода героя | 1000 (полный дневной запас) |
| список объектов | пустой |
| объект: идентификатор, вид, клетка, ресурс и количество кучки, вид шахты | **нет**: такой объект убирается. Убирается и объект вне карты, и второй объект в той же клетке |
| владелец шахты | ничья; также если номер владельца больше, чем бывает игроков. Владелец, которого нет в списке игроков, добавляется в него |
| атака и защита героя | 0 |
| опыт героя | 0 |
| уровень героя | всегда считается по опыту |
| армия героя | армия из файла `data/defaults.yaml` (сейчас 10 ополченцев). Отряд незнакомых существ или с числом меньше 1 убирается; отряды после седьмого убираются; если не осталось ни одного — та же армия из файла |
| охранник: существо, число | **нет**: такой охранник убирается. Убирается и охранник из существ, которых нет в списке существ партии, и с числом вне 1–4000 |
| сила охранника | число × 1000; так же, если целая часть силы не равна числу |
| день | 1 |
| чей ход | первый игрок; также если записан игрок, которого нет |
| список существ партии | существа из файлов игры. Записанные существа остаются как записаны (партия доигрывается с теми свойствами, с которыми началась); существа игры, которых в записи нет, добавляются в конец. Запись существа, которая не читается, убирается |
| цена и прирост существа | у существа игры с тем же идентификатором (в записях до этапа 4 этих чисел нет). Если такого существа в игре нет, запись существа убирается. Так же дописываются цена и прирост существам идущего боя |
| список зданий партии | здания из файла `data/buildings.yaml`. Записанные здания остаются как записаны; здания игры, которых в записи нет, добавляются в конец. Запись здания, которая не читается, убирается; из требований убираются здания, которых в списке нет |
| город: идентификатор, клетка, владелец | **нет**: такой город убирается. Убирается и второй город того же игрока. Владелец, которого нет в списке игроков, добавляется в него |
| постройки города | пустой список. Незнакомые и повторные здания убираются |
| строили ли сегодня в городе | нет |
| кто ждёт найма в городе | никто. Остаются только существа построенных жилищ с числом от 1; одинаковые записи складываются |
| гарнизон города | пустой. Отряд незнакомых существ или с числом меньше 1 убирается; отряды одного вида складываются |
| идущий бой | боя нет. Бой читается только целиком: если в нём хоть что-то не читается или незнакомо, если его героя или охранника нет, если армия героя или число охранника не сходятся с отрядами боя — боя нет, герой стоит на карте в зоне охранника |
| итог партии | партия идёт. Если итог — поражение, героев в записи может не быть, и новые не добавляются |
| порядковый номер записи | 0 |
| версия игры, сделавшей запись | «неизвестно» |

Каждый новый параметр состояния обязан получить строку в этой таблице в той же задаче, где он появился.

Начальные значения, которые зависят от контента игры (армия героя, существа), лежат не в коде, а в данных: `data/defaults.yaml` и `data/creatures/` (догма 8).

### Начальное состояние и список команд

Они нужны только для дампа и проверки повтором. Если при чтении текущего состояния что-то было дописано или убрано, либо начальное состояние или хоть одна команда не читаются, повтор уже не сойдётся. Тогда история сбрасывается: начальным состоянием становится текущее, список команд пуст.

### Чего это правило не умеет

Оно спасает от добавленных и убранных параметров. Если в новой версии у старого параметра изменится смысл (например, запас хода станет считаться в других единицах), начальные значения не помогут: такое изменение потребует отдельного переноса, и агент обязан сказать об этом владельцу до правки (догма 10).

## Испорченные сохранения

Обе копии испорчены или не читаются: игра сообщает, что сохранение повреждено, и предлагает новую игру. Испорченные данные можно выгрузить дампом.

## Проверка повтором

В отладочном режиме при загрузке игра повторяет партию из начального состояния и списка команд и сравнивает результат с текущим состоянием. Расхождение означает нарушение детерминизма: игра предлагает сохранить дамп.

## Свойства, верные всегда

- Сохранить и сразу загрузить — получится то же состояние.
- Оборванная запись никогда не портит предыдущую копию.
- Запись с неверной контрольной суммой никогда не загружается.
- Сохранение этой же версии читается без изменений: ничего не дописывается и не убирается.
- Что бы ни лежало в записи с верной контрольной суммой, чтение даёт либо состояние, с которым игра может работать, либо «повреждено» — но не падение.

## Крайние случаи

- Хранилище недоступно или переполнено: игра продолжает работать без сохранения и один раз показывает предупреждение.
- Сохранение есть, а запущена другая версия игры: партия продолжается по правилам раздела «Сохранения других версий».
- Одна копия от другой версии, вторая от этой: берётся целая копия с большим порядковым номером, как обычно.

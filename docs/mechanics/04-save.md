# Автосохранение

Статус: принято владельцем 2026-11-11. Этап 1.

## Что видит игрок

- Сохранение одно. Игра ведёт его сама, кнопки «сохранить» нет.
- При запуске, если есть сохранённая партия, игра предлагает «Продолжить» и «Новая игра».
- «Новая игра» при существующем сохранении спрашивает подтверждение: старая партия будет потеряна.

## Когда игра сохраняется

После каждой принятой команды.

Владелец решил сохранять «в конце каждого дня и при сворачивании приложения» (решение 0003). Сохранение после каждой команды включает оба случая и защищает ещё от одного: приложение закрыли или оно упало посреди дня. Сохранение маленькое, поэтому на скорости это не сказывается. Владелец согласился 2026-11-11.

Если команды идут быстрее, чем пишется файл, на диск попадает только самая свежая запись из очереди.

## Что лежит в сохранении

| Часть | Зачем |
|---|---|
| версия формата сохранения | чтобы распознать старое сохранение |
| версия игры | для дампа ошибки |
| текущее состояние | из него партия продолжается |
| начальное состояние и список принятых команд | для дампа ошибки и проверки повтором |
| порядковый номер записи | чтобы выбрать более свежую из двух копий |
| контрольная сумма | чтобы распознать испорченную запись |

Партия продолжается из текущего состояния, а не повтором команд с начала.

## Надёжность записи

Приложение могут закрыть прямо во время записи. Поэтому:

- Хранятся две копии сохранения. Новая запись идёт поверх более старой копии.
- При загрузке берётся копия с верной контрольной суммой и большим порядковым номером.
- Если последняя запись оборвалась, игра продолжается с предыдущей: теряется не больше одной команды.

## Где хранится

Ядро ничего не знает о хранилище. Клиент пишет сохранение через общий интерфейс «хранилище сохранений» с двумя реализациями:

- **Android:** файлы `save-0.txt` и `save-1.txt` в личной папке приложения, через дополнение Capacitor «Файлы» (`@capacitor/filesystem`, согласовано владельцем 2026-11-11).
- **Браузер (превью):** хранилище браузера.

В документации Capacitor сказано, что хранилище браузера внутри приложения система может очистить при нехватке места, поэтому на Android оно не используется: `docs/vendor/capacitor/guides/storage.md`.

## Вид записи

Запись — текст из двух строк: контрольная сумма (FNV-1a, 32 бита, восемь шестнадцатеричных цифр) и JSON с остальными частями. Версий в записи две: формата сохранения и формата состояния; несовпадение любой делает запись «старой».

## Новая игра

- Если сохранения нет, игра сразу начинает новую партию, без экрана выбора.
- Новая партия сразу записывается поверх прежней.
- «Новая игра» есть и в меню; она тоже спрашивает подтверждение. Отладочная кнопка выбора карты начинает новую партию и поэтому спрашивает так же.

## Старые и испорченные сохранения

- Обе копии испорчены или не читаются: игра сообщает, что сохранение повреждено, и предлагает новую игру. Испорченные данные можно выгрузить дампом.
- Версия формата не совпадает с текущей: до первого выпуска игры такое сохранение отбрасывается с сообщением «сохранение от старой версии». После первого выпуска старые сохранения обязаны переноситься (догма 10).

## Проверка повтором

В отладочном режиме при загрузке игра повторяет партию из начального состояния и списка команд и сравнивает результат с текущим состоянием. Расхождение означает нарушение детерминизма: игра предлагает сохранить дамп.

## Свойства, верные всегда

- Сохранить и сразу загрузить — получится то же состояние.
- Оборванная запись никогда не портит предыдущую копию.
- Запись с неверной контрольной суммой никогда не загружается.

## Крайние случаи

- Хранилище недоступно или переполнено: игра продолжает работать без сохранения и один раз показывает предупреждение.
- Сохранение есть, а запущена новая версия игры с той же версией формата: партия продолжается.

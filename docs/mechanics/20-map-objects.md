# Объекты на карте и ресурсы

Статус: принято владельцем 2026-11-12. Этап 3.

## Ресурсы игрока

- Ресурсов три: золото, дерево, руда (решение 0003).
- У каждого игрока свой запас. Запас — целые числа, не меньше нуля.
- Начальный запас задаёт файл карты.

На этапе 3 ресурсы только копятся. Тратить их можно будет в городе (этап 4).

## Что стоит на карте

| Объект | Занимает клетку | Можно пройти сквозь | Что делает |
|---|---|---|---|
| кучка ресурсов | да | нет | отдаёт ресурс тому, кто её подобрал, и исчезает |
| шахта | да | нет, но можно встать | каждый день даёт ресурс владельцу |
| охранник | да | нет | нападает на героя рядом (см. `21-guards.md`) |

- В одной клетке — не больше одного объекта. Объекты стоят только на земле.
- Герой в начале партии не стоит в клетке с объектом.

## Кучка ресурсов

- У кучки есть вид ресурса и количество.
- Количество задаётся в файле карты. Если оно не задано, выбирается случайно при создании партии: золото — 500, 600, 700, 800, 900 или 1000; дерево и руда — от 5 до 10. Так в Heroes 3.
- Герой подбирает кучку с соседней клетки: последний шаг пути ведёт на клетку кучки, герой на неё не встаёт, очки хода за этот шаг тратятся, кучка исчезает, ресурс переходит игроку. Так в Heroes 3.
- После этого клетка свободна.

## Шахта

| Шахта | Ресурс | В день |
|---|---|---|
| лесопилка | дерево | 2 |
| рудник | руда | 2 |
| золотая шахта | золото | 1000 |

Числа — из Heroes 3.

- У шахты есть владелец или его нет. В начале партии владельца нет, если файл карты не говорит иначе.
- Герой, вставший на клетку шахты, делает её своей. Шахту можно отобрать у другого игрока так же.
- Доход приходит в начале каждого дня, начиная со второго дня партии, — в ход владельца, до его первой команды. В день захвата шахта дохода не даёт.
- Герой может стоять на шахте и идти дальше. Пройти сквозь шахту без остановки нельзя: путь через неё не строится, но шахта может быть концом пути.

## Файл карты

К файлу карты из `01-adventure-map.md` добавляются поля:

```yaml
players:
  - hero:
      x: 1
      y: 1
      attack: 1
      defense: 1
      army:
        - { creature: militia, count: 20 }
        - { creature: slinger, count: 10 }
    resources: { gold: 0, wood: 0, ore: 0 }
objects:
  - { type: pile, x: 4, y: 2, resource: gold }
  - { type: pile, x: 5, y: 7, resource: wood, amount: 8 }
  - { type: mine, x: 9, y: 3, kind: sawmill }
  - { type: guard, x: 8, y: 3, creature: militia, count: 15 }
```

| Поле | Что это |
|---|---|
| `players[].hero.attack`, `defense` | начальные характеристики героя; по умолчанию — как у героя из списка героев (с шага 4.2; раньше 0) |
| `players[].hero.name` | идентификатор героя из `data/heroes.yaml`; по умолчанию первый из списка (`32-hero-hire.md`) |
| `players[].hero.army` | начальная армия героя: от 1 до 7 отрядов (см. `22-hero.md`) |
| `players[].resources` | начальный запас; по умолчанию нули |
| `objects` | объекты карты по порядку; порядок важен для детерминизма |
| `objects[].type` | `pile`, `mine` или `guard` |
| `pile.resource` | `gold`, `wood` или `ore` |
| `pile.amount` | количество; если нет — случайное |
| `mine.kind` | `sawmill`, `ore-pit` или `gold-mine` |
| `guard.creature`, `count` | существо и число существ |

Идентификаторы объектов в состоянии — по порядку в файле: `o1`, `o2`, …

## Проверка карты

К причинам отказа из `01-adventure-map.md` добавляются:

- объект стоит вне карты или на преграде;
- два объекта или объект и герой стоят в одной клетке;
- неизвестный вид объекта, ресурса, шахты или существа;
- количество в кучке или число существ меньше 1;
- герой в начале стоит на соседней с охранником клетке;
- у героя нет армии или в ней больше 7 отрядов.

## События

| Событие | Что в нём |
|---|---|
| кучка подобрана | объект, игрок, ресурс, количество |
| шахта занята | объект, новый владелец, прежний владелец |
| доход получен | игрок, сколько каждого ресурса |

## Текстовый вывод

В текстовом выводе карты (`05-diagnostics.md`) объекты показаны символами: `$` — золото, `w` — дерево, `o` — руда, `M` — шахта, `G` — охранник. Под картой — список объектов с подробностями и запас ресурсов игрока.

В сценариях (`05-diagnostics.md`) в разделе `expect` можно проверять запас и объекты (добавлено на шаге 3.1):

```yaml
expect:
  resources:
    - { gold: 100, wood: 4 } # игроки по порядку; проверяются только названные ресурсы
  objects:
    o2: absent # объекта больше нет
    o3: { owner: 0 } # владелец шахты; null — ничья
```

## Свойства, верные всегда

- Запас ресурсов не бывает отрицательным.
- Подобранная кучка исчезает и второй раз не подбирается.
- Сумма ресурсов игрока меняется только событиями «кучка подобрана» и «доход получен».
- У шахты не больше одного владельца.

## Крайние случаи

- Очков хода не хватает на последний шаг к кучке: герой останавливается раньше, кучка остаётся.
- Герой стоит на шахте, а другой герой хочет на неё встать: клетка занята героем, шаг невозможен (правило этапа 1).
- Кучка стоит в зоне охранника: чтобы подойти к ней, герой встаёт в зону — сначала бой.

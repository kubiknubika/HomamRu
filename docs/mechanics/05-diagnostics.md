# Средства наблюдения

Статус: принято владельцем 2026-11-11. Этап 1. Основание — решение 0006.

## Текстовый вывод

Ядро умеет напечатать состояние символами. Это запрос: он ничего не меняет.

```
День 9 (месяц 1, неделя 2, день 2). Ход игрока 1.
Герой A: клетка (1, 1), запас хода 718 из 1000.

   01234567
 0 ........
 1 .A#.....
 2 ..#.....
 3 ........
```

| Символ | Значение |
|---|---|
| `.` | земля |
| `#` | преграда |
| `A`, `B` | герой первого и второго игрока |
| `*` | клетка показанного пути |

Символы местности те же, что в файле карты.

## Сценарии

Сценарий — файл YAML: карта, сид и список команд. Его можно проиграть из консоли и увидеть текстовый вывод после каждой команды.

Пример для маленькой проверочной карты из `01-adventure-map.md`: герой стоит в клетке (1, 1), шагает вниз, заканчивает день и пробует шагнуть вправо, на преграду.

```yaml
name: Герой упирается в преграду
map: test-small
seed: 1
steps:
  - move: { hero: A, path: [S] }
  - endTurn: {}
  - move: { hero: A, path: [E] }
    expectError: STEP_BLOCKED
expect:
  day: 2
  heroes:
    A: { x: 1, y: 2 }
```

- Карты лежат в `data/maps/`, сценарии — в `data/scenarios/`. Имя файла карты совпадает с её `id`.
- Команду отдаёт тот игрок, чей сейчас ход.
- У шага можно указать ожидаемый отказ. Если отказа нет или он другой, сценарий провален.
- В конце можно указать ожидаемое состояние: день, клетку героя и, если нужно, остаток запаса хода (`movement`).
- С этапа 3 сценарий карты может содержать шаги боя и новые ожидания — раздел «Шаги боя в сценарии карты» ниже.
- Запуск из консоли: `pnpm run play` проигрывает все сценарии, `pnpm run play data/scenarios/имя.yaml` — один.
- Каждый сценарий из папки сценариев автоматически проигрывается как тест.

Ошибка, найденная в игре, сначала записывается сценарием, который её воспроизводит, и только потом исправляется (догма 9).

### Шаги боя в сценарии карты

Добавлено на шаге 3.2 (`23-map-battle.md`, «Сценарии»).

```yaml
name: Герой входит в зону охранника и побеждает
map: test-guards
seed: 1
steps:
  - move: { hero: A, path: [E, E, SE] }
  - endTurn: {}
    expectError: BATTLE_IN_PROGRESS
  - fight: {}
expect:
  battle: false
  outcome: none
  heroes:
    A: { x: 3, y: 1, experience: 180, level: 1, skills: 2 }
  objects:
    o1: absent
    o2: { owner: 0 }
```

| Шаг | Что делает |
|---|---|
| `move: [столбец, ряд]`, `attack: { target, from }`, `shoot: отряд`, `wait: {}`, `defend: {}`, `flee: {}` | команда боя — те же шаги, что в сценарии боя (`16-battle-screen.md`). Команду отдаёт сторона, чей отряд сейчас ходит: сценарий может ходить и за охранника |
| `fight: {}` | «бой до конца»: идущий бой доигрывает простой компьютер за обе стороны. Если боя нет, сценарий провален |

Шаг `move` с героем и путём — команда карты, с клеткой поля боя — команда боя.

У шага боя можно ожидать и отказ партии (`NO_BATTLE`, `GAME_OVER`), и отказ боя (`NOT_A_SHOOTER` и другие из `12-battle-actions.md`).

| Ожидание | Что сверяется |
|---|---|
| `battle: true` или `false` | идёт ли бой в конце сценария |
| `outcome: none` или `defeat` | итог партии |
| `heroes.<id>: absent` | героя нет на карте |
| `heroes.<id>.experience`, `level` | опыт и уровень героя |
| `heroes.<id>.skills` | атака плюс защита: что именно выросло с уровнем, решает случай |
| `heroes.<id>.army` | армия целиком: список отрядов по порядку |
| `objects.<id>: { count }` | число существ у охранника |

Клетку героя теперь можно не указывать.

## Журнал событий

Описан в `00-state-and-commands.md`. В текстовом выводе события печатаются по одному в строке, например: «Герой A: шаг (1, 1) → (2, 1), потрачено 100, осталось 900».

## Дамп ошибки

Дамп — один файл JSON, по которому агент точно воспроизводит ситуацию.

| Часть | Что в ней |
|---|---|
| версии | версия игры, версия формата состояния |
| партия | начальное состояние и все принятые команды |
| состояние | текущее состояние |
| журнал | события последних 200 команд |
| ошибка | текст и место ошибки, если она была |
| устройство | размер экрана, плотность пикселей, система, браузер |
| время | дата и время создания дампа |

Личных данных в дампе нет.

Дамп создаётся двумя способами:

- **Автоматически.** Игра поймала ошибку — игрок видит сообщение «Что-то пошло не так» и кнопку «Сохранить дамп».
- **Вручную.** Кнопка «Сохранить дамп» в меню — для случаев, когда игра не упала, но ведёт себя неправильно.

Кнопка открывает системное окно «Поделиться» (на телефоне, через дополнение Capacitor `@capacitor/share`, согласовано владельцем 2026-11-11) или скачивает файл (в браузере). Сам по себе дамп никуда не отправляется.

Экран «Что-то пошло не так» можно закрыть и играть дальше: партия уже сохранена.

Если сохранение повреждено, в дамп попадают обе нечитаемые копии как есть.

Агент получает дамп от владельца и проигрывает его из консоли так же, как сценарий: `pnpm run play путь/к/дампу.json`. Консоль повторяет партию, печатает карту, дату и клетку героя и сверяет результат с состоянием из дампа.

## Счётчик кадров

В отладочном режиме в углу экрана показаны три числа за последние три секунды: средняя частота кадров, наименьшая частота и самый долгий кадр в миллисекундах. По ним владелец проверяет скорость на телефоне.

До первого выпуска игры отладочный режим включён всегда.

## Крайние случаи

- Ошибка случилась до создания партии: дамп содержит только версии, ошибку и сведения об устройстве.
- Дамп очень длинной партии: команды сохраняются все, журнал — только последние 200 команд.

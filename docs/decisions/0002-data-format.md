# 0002. Формат данных контента

Дата: 2026-11-11. Статус: форматы приняты, правило выбора между ними предложено и ждёт подтверждения.

## Принято

Основной формат — JSON. YAML используется иногда.

## Предложено, ждёт подтверждения

- JSON — для сущностей с характеристиками: существа, заклинания, здания, артефакты, навыки, фракции.
- YAML — для файлов, где много текста или нужны комментарии: локализация, сценарии, события на карте.
- Один тип контента — один формат. Смешивать форматы внутри одного типа нельзя.
- Один файл на сущность, папка на тип: `data/creatures/`, `data/spells/` и так далее.
- Оба формата проверяются одними и теми же схемами Zod; типы в коде выводятся из схем.
- Названия и описания лежат в файлах локализации, в данных — только ключи.
- Пояснения в JSON — в необязательном поле `note`.

## Почему

- JSON агенты пишут без ошибок, для него лучшие инструменты проверки.
- YAML удобнее для длинных текстов и допускает комментарии.
- Единая схема не даёт данным и коду разойтись.

## Что отвергли

- TOML: неудобен для вложенных структур.
- Таблицы как источник истины: плохо для вложенных данных. Выгрузка баланса в таблицы и обратно возможна позже.
- Данные прямо в коде: нарушает догму 8.

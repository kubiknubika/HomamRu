# 0001. Стек проекта

Дата: 2026-11-11. Статус: основа принята, состав компонентов предложен и ждёт подтверждения.

## Требования владельца

- Платформы по очереди: Android, затем Windows, затем остальные. Консоли — в самом конце.
- Сетевая игра не в приоритете. Когда появится: свой сервер (селфхостинг) или игра с одного телефона.
- Вид игры — 2D, как в третьей части серии.
- Владелец не читает код: результат проверяется тем, что игру можно посмотреть и потрогать.
- Язык ядра со строгой типизацией, чтобы агенту было легко отлаживать.

## Принято

- Язык: TypeScript в строгом режиме.
- Игра — веб-приложение: отрисовка на PixiJS, упаковка под Android через Capacitor.
- Идентификаторы в коде — на английском; документация и комментарии — на русском.

## Предложено, ждёт подтверждения

| Роль | Компонент |
|---|---|
| Компилятор и проверка типов | TypeScript 7, режим `strict` |
| Отрисовка карты и боя | PixiJS 8 |
| Интерфейс (окна, меню, списки) | HTML и CSS поверх холста, на React |
| Упаковка под Android | Capacitor |
| Упаковка под Windows | Tauri 2 (решается, когда дойдём до Windows) |
| Сборка | Vite 8 |
| Тесты | Vitest |
| Линтер и форматтер | Biome |
| Поиск мёртвого кода | Knip |
| Схемы данных | Zod |
| Пакеты | pnpm, монорепозиторий: `core`, `data`, `client`, позже `server` |
| Сборка APK | GitHub Actions |

## Почему

- Этот стек модели знают лучше всего, а игру видно в браузере сразу после изменения.
- Ядро на TypeScript запускается на Node без окна: быстрые тесты сейчас, тот же код на своём сервере потом.
- PixiJS — только отрисовка, без игровой логики. Это совпадает с догмой 5: правила живут в ядре.
- Интерфейс на HTML и CSS: в игре очень много окон, а вёрстка для них удобнее ручной расстановки на холсте.
- Отдельные пакеты физически запрещают ядру зависеть от отрисовки.

## Что отвергли

- Godot + C#: экспорт C# на Android помечен как экспериментальный, экспорта в браузер нет.
- Godot + GDScript: необязательная типизация, ядро не отделяется от движка.
- MonoGame + C#: нет готового интерфейса и живого превью. Запасной вариант, если консоли станут важнее.
- libGDX + Kotlin: нет консолей, модели знают хуже.
- Unity + C#: работа завязана на редактор.
- Phaser 4: полный игровой фреймворк с физикой и сценами; нам нужна только отрисовка.

## Известные риски

- Консоли этим стеком практически закрыты.
- Производительность WebView на недорогих Android-устройствах разная. Первый же прототип карты проверяется на реальном телефоне среднего класса.
- Android SDK в песочнице агента недоступен: APK собирается только в CI.
